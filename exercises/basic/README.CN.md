# 实现基础转发

## 介绍

本练习的目标是编写一个实现基础转发功能的P4程序。为了简化，我们将只实现IPv4的转发。

使用IPv4转发时，交换机必须对每个数据包执行以下操作：(i)更新源和目标MAC地址，(ii)递减IP头部中的生存时间(TTL)，以及(iii)通过适当的端口转发数据包。

您的交换机将有一个单一的表，控制平面将使用静态规则填充该表。每条规则将IP地址映射到下一跳的MAC地址和输出端口。我们已经定义了控制平面规则，因此您只需要实现P4程序的数据平面逻辑。

我们将为本练习使用以下拓扑。这是胖树拓扑的单个pod，以下称为pod-topo：
![pod-topo](./pod-topo/pod-topo.png)

我们的P4程序将为P4.org的bmv2软件交换机实现的V1Model架构编写。V1Model的架构文件可以在以下位置找到：/usr/local/share/p4c/p4include/v1model.p4。该文件描述了架构中P4可编程元素的接口、支持的扩展，以及架构的标准元数据字段。我们鼓励您查看它。

> **剧透警告：** 在`solution`子目录中有一个参考解决方案。随时可以将您的实现与参考进行比较。

## 步骤1：运行（不完整的）起始代码

包含此README的目录还包含一个P4程序骨架，`basic.p4`，它最初会丢弃所有数据包。您的任务是扩展这个骨架程序，使其能够正确转发IPv4数据包。

在此之前，让我们编译不完整的`basic.p4`，并在Mininet中启动一个交换机来测试其行为。

1. 在您的shell中，运行：
   ```bash
   make run
   ```
   这将：
   * 编译`basic.p4`，并
   * 在Mininet中启动pod-topo，并使用适当的P4程序+表项配置所有交换机，并
   * 使用[pod-topo/topology.json](./pod-topo/topology.json)中列出的命令配置所有主机

2. 您现在应该看到Mininet命令提示符。尝试在拓扑中的主机之间进行ping测试：
   ```bash
   mininet> h1 ping h2
   mininet> pingall
   ```
3. 输入`exit`退出每个xterm和Mininet命令行。
   然后，要停止mininet：
   ```bash
   make stop
   ```
   要删除所有pcap文件、构建文件和日志：
   ```bash
   make clean
   ```

ping测试失败是因为每个交换机都按照`basic.p4`编程，它会在到达时丢弃所有数据包。
您的任务是扩展此文件，使其能够转发数据包。

### 关于控制平面的说明

P4程序定义了一个数据包处理管道，但表中的规则是由控制平面插入的。当规则匹配数据包时，会调用其动作，动作的参数由控制平面作为规则的一部分提供。

在这个练习中，我们已经为您实现了控制平面逻辑。作为启动Mininet实例的一部分，`make run`命令将在每个交换机的表中安装数据包处理规则。这些规则在`sX-runtime.json`文件中定义，其中`X`对应于交换机编号。

**重要提示：** 我们使用P4Runtime来安装控制平面规则。文件`sX-runtime.json`的内容引用了编译器生成的P4Info文件中定义的特定表名、键和动作（运行`make run`后查找文件`build/basic.p4.p4info.txtpb`）。P4程序中添加或重命名表、键或动作的任何更改都需要反映在这些`sX-runtime.json`文件中。

## 步骤2：实现L3转发

`basic.p4`文件包含一个P4程序骨架，其中关键逻辑部分被`TODO`注释替换。您的实现应遵循该文件中给出的结构——用实现缺失部分的逻辑替换每个`TODO`。

完整的`basic.p4`将包含以下组件：

1. 以太网（`ethernet_t`）和IPv4（`ipv4_t`）的头部类型定义。
2. **TODO：** 解析以太网和IPv4的解析器，用于填充`ethernet_t`和`ipv4_t`字段。
3. 使用`mark_to_drop()`丢弃数据包的动作。
4. **TODO：** 一个名为`ipv4_forward`的动作，它：
	1. 为下一跳设置出口端口。
	2. 用下一跳的地址更新以太网目标地址。
	3. 用交换机的地址更新以太网源地址。
	4. 递减TTL。
5. **TODO：** 一个控制，它：
    1. 定义一个表，该表将读取IPv4目标地址，并调用`drop`或`ipv4_forward`。
    2. 一个应用该表的`apply`块。
6. **TODO：** 一个解析器，它选择字段插入到输出数据包中的顺序。
7. 提供解析器、控制和解析器的`package`实例化。
    > 通常，一个包还需要校验和验证和重新计算控制的实例。这些对于本教程不是必需的，而是用空控制的实例化代替。

您解决方案的"测试套件"——在拓扑中的主机之间发送ping——并不是很健壮。您还应该测试什么，以确信您的实现是正确的？

 - 您将如何增强您的程序以支持traceroute？
 - 您将如何增强您的程序以支持下一跳？

### 故障排除

在开发程序过程中可能会出现几个问题：

1. `basic.p4`可能无法编译。在这种情况下，`make run`将报告编译器发出的错误并停止。

2. `basic.p4`可能会编译，但无法支持`make run`尝试使用P4Runtime安装的`s1-runtime.json`到`s3-runtime.json`文件中的控制平面规则。在这种情况下，如果控制平面规则无法安装，`make run`将报告错误。使用这些错误消息修复您的`basic.p4`实现。

3. `basic.p4`可能会编译，控制平面规则可能会安装，但交换机可能不会以所需的方式处理数据包。`logs/sX.log`文件包含详细的日志，描述每个交换机如何处理每个数据包。输出非常详细，可以帮助您找出实现中的逻辑错误。

#### 清理Mininet

在上述后两种情况下，`make run`可能会在后台留下一个Mininet实例运行。使用以下命令清理这些实例：

```bash
make stop
```

## `topology.json`中网关(gw)和ARP命令的使用
- 网关(gw)命令：`route add default gw`命令用于设置主机的默认网关。这告诉主机如果目标IP不在同一子网上，应该将数据包发送到哪个IP地址。主机知道其默认网关对于与本地网络外的设备通信非常重要。
- ARP命令：`arp -i eth0 -s`命令用于向主机的ARP缓存添加静态ARP条目。当您添加静态ARP条目时，您实际上是在告诉计算机："嘿，我已经知道谁住在这个IP地址（如10.0.0.1），所以你不需要一直在网络上问'谁拥有这个IP？'"这在本练习（和大多数其他练习）中特别重要，因为交换机不响应ARP请求。在真实网络中，生产交换机通常会响应ARP请求，但在这些练习中，由于这种行为，网关路由器需要静态ARP条目。
  - `-i eth0`：指定要执行ARP操作的网络接口（例如eth0）。
  - `-s`：此标志用于设置静态ARP条目。

*注意*：如果您移除网关和ARP命令，网络中的主机可能会失去相互之间以及与本地子网外设备的连接。这可能导致运行`pingall`命令时出现100%的数据包丢失，因为主机没有必要的路由信息和ARP条目来到达目的地。
